# Field night 2026-08-20 — SP Create/AE2 stress

Reconciled from live field worktree on 2026-08-20. Raw local bench artifacts
remain outside this focused lead-doc commit.

## Pack

NeoForge 1.21.1, Weft 0.1.0-alpha, Create, AE2, Spark, FerriteCore,
ModernFix, Sodium/Iris. Moonrise was present during early boots and removed for
later parallel testing after a crash.

## Crashes

1. Create boot: `IncompatibleClassChangeError` involving `SchematicLevel` and
   final `Level.getEntitiesOfClass`; Moonrise suspected. Removing Moonrise let
   one pack iteration boot. Not yet isolated enough for a Weft claim.
2. Server tick: Moonrise `TickThread.ensureTickThread` fired from a Weft
   ForkJoin worker during `RegionizedTicking` entity work under
   `parallelRegions`: `Cannot execute main thread task off-main`. Tracked as
   issue #16.

## ON versus OFF sample

- ON Spark: https://spark.lucko.me/4tZEpenm9v — TPS 20; MSPT median 8.99,
  p95 14.3, max 44.1.
- OFF Spark: https://spark.lucko.me/2AZEbxNQ0H — TPS 20; MSPT median 10.1,
  p95 21.4, max 72.8.
- Weft metrics often showed `owned parallel=0` during ON. Multi-region topology
  is not proof of worker fan-out, so do not attribute the improvement solely to
  parallel regions.
- `weft-report` modeled about 1.46x for four hypothetical regions / 68% hot
  villagers. This is model output, not an in-world speedup claim.

## Product implications

- Keep P1 and latency-tail claims scoped to measured evidence.
- `/weft status` and exported metrics must make actual fan-out visible.
- Moonrise + region ownership must yield/refuse until coexistence is designed
  and tested. Do not run or recommend Moonrise + parallel soak meanwhile.
- Keep live dashboard and thread-CPU observation for future field work.
